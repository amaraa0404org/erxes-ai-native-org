## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.2-01 | Information Disclosure | `decryptSecret` error path | mitigate | When all key versions fail, throw `SecretRotationRequiredError` with subdomain + envelopeVersion only — never include any portion of the failed ciphertext, IV, or attempted keys. Unit test asserts thrown error's `.message` and `.stack` contain neither `iv` nor `ciphertext` substrings. |
| T-01.2-02 | Information Disclosure | `parseSecretVersions` warn channel | mitigate | When skipping short keys, log only the version label (`v2:` etc.) and the `bytes` count — never the key material itself. Idempotent (warn-once `Set`) so a misconfigured deployment does not flood logs with repeated key fragments. |
| T-01.2-03 | Tampering | npm package install | accept | `openai` (OpenAI Inc.), `@anthropic-ai/sdk` (Anthropic), `@google/genai` (Google) are all first-party SDKs from the vendor of the respective service — provenance is the same as the vendor's domain. No supply-chain audit gate triggered (no `[ASSUMED]`/`[SUS]` packages — these are vendor-owned). |
| T-01.2-04 | Denial of Service | iterate-all-versions on every decrypt | accept | Worst case is N scrypt + N decipher attempts per decrypt call. With N <= 3 (typical: 1 active version, 1 grace version during rotation), overhead is bounded ~30ms. Scrypt parameters from Phase 1.1 are unchanged. Document the multi-version cost in `encryption.ts` header. |
| T-01.2-05 | Repudiation | Multi-version rotation log | mitigate | `console.warn` on short-key skip includes the version label so audit reconstructions of "which keys were active when" are possible. Rotation script (Plan 09) preserves which version originally encrypted each row in its own log output. |
| T-01.2-SC | Tampering | npm installs (openai, @anthropic-ai/sdk, @google/genai) | accept | All three packages are vendor-owned (OpenAI / Anthropic / Google). RESEARCH.md does not ship a "Package Legitimacy Audit" table because Phase 1.1 added zero provider SDKs (D-13 forbid it). Phase 1.2 adds first-party vendor SDKs only — no [ASSUMED] or [SUS] packages. Researcher's STACK.md §A pins are reused; D-04 supersedes the Google portion only. |
