# Phase 01.2 Plan 01: Encryption Rotation + Errors Module + SDK Pins Summary

**Multi-version ERXES_SECRET decrypt with SecretRotationRequiredError gate, four shared AI error classes (AIError + 4 concrete subclasses), and three pinned vendor SDKs (openai@^6.38.0, @anthropic-ai/sdk@^0.97.1, @google/genai@^2.5.0) — all consumable from `erxes-api-shared/ai`.**

## Accomplishments

- **Multi-version rotation (D-03 / PROV-06):** `decryptSecret(envelope, subdomain)` now iterates every configured `vN:<hex>` entry in `ERXES_SECRET` newest-first. The first scrypt-derived key whose AES-GCM auth tag validates returns the plaintext. When all versions are exhausted, a `SecretRotationRequiredError` is raised with `subdomain` and `envelopeVersion` only (no ciphertext, no IV, no key material — T-01.2-01).
- **Errors module:** `backend/erxes-api-shared/src/ai/errors.ts` ships `AIError` base class plus four concrete subclasses (`SecretRotationRequiredError`, `BudgetExceededError`, `NotYetImplementedError`, `ProviderRateLimitError`). Every subclass extends `AIError` → `Error`, sets `name` from `new.target.name`, and exposes its detail properties as readonly own-enumerable fields. Re-exported via `export * from './errors'` in the `erxes-api-shared/ai` barrel.
- **SDK pins (D-04 + D-05b):** Three vendor-owned SDKs added to `backend/erxes-api-shared/package.json` dependencies, sorted alphabetically with existing deps. `pnpm-lock.yaml` regenerated and verified to contain resolved tarball entries for all three.
- **Coverage uplift:** `src/ai/encryption.ts` coverage now **92.77% statement / 92.2% lines / 100% function** (up from Phase 1.1's 86.36%). `src/ai/errors.ts` ships at **100% lines / 100% statements / 100% functions**.
- **No regression:** All 38 prior Phase 1.1 tests still pass; new total 53 tests across 5 suites.
