`@google/genai` v1.x API (modern, Node 22+ engine compatible per D-04):
```typescript
import { GoogleGenAI } from '@google/genai';
const ai = new GoogleGenAI({ apiKey });
const models = await ai.models.list();  // iterator → Pageable<Model>
// model.name = 'models/gemini-1.5-pro', model.supportedActions = ['generateContent','embedContent',...]
```

Ollama REST shape (no SDK; raw fetch):
- `GET ${baseUrl}/api/tags` → `{ models: [{ name: 'llama3.2:latest', size: ..., details: { family, parameter_size } }] }`
- `GET ${baseUrl}/api/version` → `{ version: '0.x.y' }`
- baseUrl is typically `http://localhost:11434` (no auth) but admins may proxy through reverse-auth, hence `apiKey` is still in ProviderConstructorArgs and is sent as `Authorization: Bearer <apiKey>` IF present (Ollama itself ignores it, proxy may not).

Custom (OpenAI-compatible) uses the same `openai` SDK as OpenAIProvider but constructs with `baseURL` from ProviderConstructorArgs. Covers LiteLLM proxy, vLLM, Together, Groq (when configured as OpenAI-compatible), OpenRouter, Cloudflare AI Gateway, etc. — same JSON shape, same /v1/models endpoint.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ollama baseUrl → fetch URL construction | Admin provides baseUrl (typically http://localhost:11434). Mitigation: trailing-slash normalization + AbortController 10s timeout. |
| `this.apiKey` retention in OllamaProvider | Raw fetch has no SDK-side credential store, so the adapter retains `apiKey` on the instance. Mitigated by documenting "never serialize / never log this instance". |
| @google/genai SDK exception chain | Same P1 surface as OpenAI/Anthropic — every error must pass through `redactKey()` before bubbling. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.2-15 | Information Disclosure (P1) | Google/Ollama/Custom error chains | mitigate | Every catch block runs `redactKey(message)` before assigning to ProviderError. Tests 2, 5 (Google + Ollama) explicitly assert sanitization. |
| T-01.2-16 | Information Disclosure | OllamaProvider `this.apiKey` retention | mitigate | Documented in header. Adapter instances are created per-request inside `resolveProvider` (Plan 05) and discarded after testConnection — no long-lived state. |
| T-01.2-17 | DoS | Slow Ollama probe hanging the UI | mitigate | AbortController with 10s timeout on every fetch — Ollama probe cannot exceed PROV-05's 10s SLO. |
| T-01.2-18 | Tampering | Custom provider baseUrl injection | accept | baseUrl is admin-set in `ai_providers` — admin DB access is required to attack. Same threat surface as Phase 1.1's Qdrant URL config. |
| T-01.2-SC | Tampering | npm/yarn registry — @google/genai | accept | First-party vendor SDK from Google. Same threat profile as Plan 01 T-01.2-SC. Resolved version logged in Plan 01 SUMMARY. |
