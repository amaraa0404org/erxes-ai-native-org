## Accomplishments

- **Atomic pre-check primitive (BUDG-02, P2 mitigation):** `checkBudget` ships verbatim the D-02 pattern — `redis.incrby` → over-cap detection → `redis.decrby` rollback + `BudgetExceededError` throw. Per-key incrby atomicity is the race-safety boundary — 100 concurrent invocations cannot both pass an over-cap check (Plan 09 integration test will prove this at 100× against real Redis).
- **XCUT-08 acceptance gate proven at unit level (Test 7):** `monthlyUsdCap === 0` → `capCents === 0`. Any positive `estimatedCents` (the estimator returns ≥ 1¢ for non-empty input) yields `newSpend > 0 > capCents`, throwing `BudgetExceededError` on the first chargeable call. The full integration proof (chat-call-through-the-budget-gate) lands in Plan 09's race + XCUT-08 test.
- **Reconcile + release (BUDG-03):** `reconcileBudget` applies the signed `actualCents - estimatedCents` delta via `incrby`, refreshing TTL on every call so the bucket auto-expires when the month rolls over. `releaseBudget` handles the provider-failure path (Phase 1.3's `try/catch` calls this when `provider.chat()` throws).
- **Cost estimator (P7 + P8 mitigation):** `estimateCostCents` uses `COST_TABLE × DRIFT_MULTIPLIER` with `Math.ceil` rounding so the pre-check never under-reserves. Unknown models fall back to a conservative default (5/15 USD per 1M for in/out × 1.2 drift), which over-estimates and is then reconciled down by `reconcileBudget` after the provider returns `usage`. The `toolDefsOverheadTokens` parameter mitigates P8 (tool definition JSON Schemas inflate the token budget).
- **Alert-threshold pubsub (D-02c, BUDG-05 storage):** `emitThresholdCrossed` publishes `ai:budget:threshold:{subdomain}:{scope}:{scopeId}` on first crossing of each configured fraction. At-most-once-per-month is guaranteed by atomic SADD against `ai:budget:threshold:fired:{subdomain}:{scope}:{scopeId}:{monthlyKey}` — only the agent whose SADD returns 1 publishes. Phase 1.3 wires the audit-log subscriber; Phase 3.1 wires the `ai:budgetExceeded` automation trigger.
- **Resolvers (BUDG-01, BUDG-06):** `aiBudgetsSet` (idempotent upsert via the model's compound-unique key) + `aiBudgetsRemove`; `aiBudgets(scope?)` + `aiBudget(_id)` queries — both augment every response with the LIVE Redis `currentMonthSpend` so the Phase 1.4 settings UI sees fresh data. Mongo's stored value is the nightly-reconciled fallback (Phase 1.3 owns the writer).

## Decisions Made

- **No new dependencies added.** Zero `package.json` delta. The Redis client and ioredis package are already in `erxes-api-shared`; `Zod` is already in the project.
- **Plan's "AI_BUDGET_DEFAULT_USD" env-driven fallback was deferred to Phase 1.3.** Plan 07's spec said: "if AI_BUDGET_DEFAULT_USD is set, use it as the default; if absent or 0, treat as unlimited." Phase 1.2 does NOT ship the env-driven default — absence of a row = unlimited; explicit `$0` cap = XCUT-08. The reasoning (in the plan itself): scope resolution chain (user → team → workspace fallback) is owned by Phase 1.3's call site, so layering an env-default on top of an unresolved scope makes no semantic sense here. Documented inline in `check.ts`.
- **Test scope vs. integration scope.** Unit tests mock `redis` (jest spies for incrby/decrby/get/expire/sadd/publish) and use the REAL `BudgetExceededError` (imported from `erxes-api-shared/ai`). This proves the contract — payload shape, atomic-rollback-before-throw ordering — without spinning up a real Redis. The integration test at 100× concurrent against real Redis lives in Plan 09 (a separate execution wave with the `budget-race.test.ts` file).
